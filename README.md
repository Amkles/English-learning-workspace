# Prompt Lab · 提示词工程实验集

> 把一段长提示词，做成**能跑、能测、能改**的东西。

这里放的是用提示词工程产出的完整工作台。每个工作台配齐五样东西：**提示词原文、可运行产物、断言式测试、设计文档、在线地址**。提示词和产物放在同一层目录里，改了哪一句、生成出什么，能一一对上。

**当前收录 2 个工作台 · 最后更新 2026-11-10**

在线入口：<https://amkles.github.io/prompt-lab/>

## 两个分类各放什么

**`english-learning/`** 放英语学习相关的工作台。目前只有六级打卡台一个项目，覆盖单词、阅读、听力、翻译、写作五个板块，按天推送内容并按池长反推冷却天数，保证整池轮完才回头。以后加雅思、考研英语之类的项目，直接在这个目录下新开子目录。

**`academic-workspace/`** 放学术研究相关的工作台。目前是硕士学术工作台，任务管理、研究进度看板、习惯打卡三块双向绑定：看板加任务会进今日待办，任一边标记完成另一边同步，删月任务连带删看板进度任务。这个目录本身就是项目，`index.html` 在根。

## 每个工作台必备的五样东西

1. **提示词原文**：逐字保留，写清约束、验收用例和踩过的坑。改提示词就是改版本，别边做边补。
2. **可运行产物**：双击能开。有构建步骤的，产物提交进仓库，CI 重建后逐字节比对。
3. **断言式测试**：断言行为，不断言外观。抽取类逻辑跑长时间跨度压测（六级打卡台跑 400 天）。
4. **设计文档**：算法、数据结构、联动规则写清楚，接手的人能只靠文档改代码。
5. **在线地址**：Pages 自动部署，手机上能直接用。

---

## 六条硬约束

任何项目都不能破：

1. **产物要能独立运行**。单文件就真的单文件，不偷偷引 CDN；引了依赖就在 README 里写清装什么。
2. **内容池不许放占位符**。「示例文章 1」「题目待补充」不算内容，只会掩盖排版问题。
3. **不采集用户数据**。本地存档放 `localStorage`，不上报、不埋点、不要求注册。
4. **不提交密钥**。API key、token、cookie 一律不进仓库。
5. **不写个人隐私**。真实姓名、学校、导师、手机号、身份证号不进任何文件，包括测试数据和截图。
6. **产物与源码必须同步**。改源码不重新构建就提交，CI 会红。

## 怎么加新项目

1. 判断归哪个分类，在对应文件夹下新建子目录（`academic-workspace/` 这类目录本身就是项目，直接放文件）。

```
<分类>/<slug>/
├── README.md            必备：是什么、怎么跑、截图、已知限制
├── PROMPT.md            提示词原文
├── src/                 源码（无构建步骤的项目可省略）
├── data/                内容池（如有）
├── tests/               断言式测试（有逻辑就要有）
├── docs/                设计文档与截图
└── index.html           产物
```

2. 在本 README 的「现在能用的」表格加一行，更新顶部「当前收录 / 最后更新」，在「更新记录」补一条。
3. 在 `.github/workflows/` 加测试 job，可复制 `english-learning-test.yml` 改路径；单文件无构建的项目，CI 只需检查产物里没有外链资源。
4. 需要上线的话，在 `pages.yml` 的「准备站点目录」里加一行 `cp`，并在 `.github/pages/landing.html` 加入口卡片。

## 测试与代码风格

- **断言行为，不断言外观**。外观交给截图人工看，逻辑交给断言。
- **用长时间跨度压测**。抽取类逻辑跑 400 天，能暴露「前 30 天正常、之后开始重复」。
- **测边界，不测主流程**。主流程肉眼能看出来，边界不能：池子比需求小、解析结果为 0、跨月、跨年、同一天刷新两次。
- 测试不依赖真实日期的副作用；要么注入日期，要么开头把状态清干净。
- 注释和提交信息用中文，术语保留英文原文（`localStorage`、`Fisher–Yates`）。提交信息第一行不超过 50 字，正文说清为什么改；一次提交做一件事。

提 PR 前：

```bash
cd english-learning/cet6-daily
python tools/build.py            # 有构建的话，确认产物可重复
cd tests && npm ci && npm test   # 三套测试全绿
```

## 已知限制

- **仓库整体是中文的**，代码注释、提交信息、文档都以中文为主
- 每个项目各自独立、各带依赖，没有统一的 monorepo 工具链——单文件产物不该被构建系统绑架
- Pages 一个仓库只能发布一个站点，所以两个工作台挂在同一域名下的不同路径，入口页在根
- 学术工作台没有构建步骤和自动化测试，`index.html` 就是源码，改动靠人工验收
