# 用 AI 生成同款：完整提示词与生成说明

这份工作台不是手写出来的，是**一段提示词 + 若干轮验收**的产物。这里把原始提示词、生成流程、验收清单全部公开——你可以照抄提示词生成自己的版本，也可以拿它当"一份 AI 产出到底能不能用"的对照标准。

生成工具是 WorkBuddy 的「工作台搭建师」专家（小台），底层模型负责写代码，专家的规范负责约束质量。

---

## 1. 完整提示词（可复制）

下面这段就是当初用的原始提示词，只做了一处改动：把自己的研究线与习惯换成了通用名称，避免公开仓库暴露选题方向。复制后把 `{}` 里的内容换成你自己的。

```text
请帮我生成一个「硕士学术工作台」的单文件 HTML 页面，用于我硕士阶段的日常学习与研究管理。要求如下：

【一、三个功能模块】
1. 任务管理（四维度）
- 用子Tab切换四个维度：今日 / 本周 / 本月 / 全部
- 每个维度有独立任务列表，支持添加、勾选完成、删除
- 任务字段：内容、优先级（P0红/P1黄/P2蓝）、可关联研究线
- 每个维度顶部显示统计：总数 / 已完成 / 待完成 / 完成率

2. 研究进度看板
- 展示多条「研究线」（研究项目），每条线有名称、专属颜色、完成进度条
- 每条线下有「进度任务」列表，任务状态点击循环切换：待启动 → 进行中 → 已完成
- 支持添加、删除进度任务；支持删除整条研究线（二次确认）

3. 习惯打卡
- 多个习惯卡片，每个习惯可「今日打卡」（再次点击取消）
- 打卡视图三档切换：本周（7天横排日历）/ 本月（月历网格）/ 全部（按月统计条形图）
- 显示连续打卡天数

【二、核心联动逻辑（务必实现，这是重点）】
1. 研究看板添加进度任务时，提供「同步今日」勾选框（默认勾选）→ 自动在今日待办创建同名关联任务
2. 任务管理添加任务时若关联了某条研究线 → 研究看板对应线下自动新增进度任务
3. 在「全部」维度添加任务（即总任务）→ 自动创建一条新的研究线（以任务命名），总任务成为该线第一个进度任务，无需手动关联
4. 双向状态联动：任一边标记完成，关联的另一边自动同步完成
5. 删除对称：删月/总任务时连研究看板对应进度任务一起删；删今日/本周任务时只解除关联、研究任务保留
6. 研究看板任务根据关联维度显示彩色小标签（今日蓝/本周黄/月任务绿/总任务紫）

【三、页面顶部置顶区】
- 置顶「今天要处理」区域，列出：逾期未完成 + 今日到期任务
- 逾期项红色标注，每项给「顺延今天」和「完成」一键按钮
- 昨天没完成的自动顺延展示，不凭空消失

【四、技术规范（硬性要求）】
- 单文件 HTML，所有 CSS/JS 内联，禁止引用任何外部框架、CDN、字体、图表库
- 图标用内联 SVG，图表用内联 SVG 手写，禁止用 emoji 当图标
- 数据存 localStorage，刷新不丢失
- 响应式：PC 顶部导航，移动端底部 Tab；按钮点击区≥44px，输入框字号≥16px
- 适配 iPhone 底部安全区（env(safe-area-inset-bottom)）
- 首次打开预置 3-5 条示例数据（其中至少 1 条逾期状态），附「清空示例」能力
- 设置里提供「导出 JSON 备份」「导入恢复」「清空全部数据（二次确认弹窗）」

【五、我的个性化信息（请按此预置示例数据）】
- 研究线：{毕业论文}、{期刊投稿}、{课程论文}、{内容运营}
- 习惯：{每日阅读}、{运动30分钟}、{每周输出}

【六、视觉风格】
- 主色靛蓝 #3B5BDB，白底、圆角卡片、浅灰背景
- 学术简洁风，系统字体栈（-apple-system 等）

请直接输出完整可运行的 HTML 代码。
```

## 2. 这六段要求各自在防什么

提示词写得不算短，但没有一条是凑数的。每一段都在封堵 AI 生成网页时的一类典型失败。

| 要求 | 在防什么 | 不这么写会怎样 |
|---|---|---|
| 「单文件、禁止 CDN / 框架 / 图表库」 | 用户只保存了 HTML，外链资源在离线或被墙时 404 | 页面白屏或功能全废，且用户无法自行修复 |
| 「图标用内联 SVG，禁止 emoji」 | emoji 的渲染由系统字体决定 | Windows 上是彩色卡通 emoji，与"学术简洁风"直接冲突，且不同设备长得不一样 |
| 「核心联动逻辑（务必实现），逐条编号」 | AI 天然倾向把三个模块各做各的 | 得到三个独立的统计页面，而不是一个能互相联动的系统 |
| 「双向状态联动 / 删除对称」写清正反两个方向 | 只说"联动"，实现方会只做单向 | 从看板标记完成能同步，从任务勾选完成却不同步，用两天就会发现不一致 |
| 「昨天没完成的自动顺延，不凭空消失」 | 按日期过滤最容易把过期项过滤掉 | 昨天没做完的任务今天彻底看不见，等于数据静默丢失 |
| 「示例数据至少 1 条逾期」 | 空页面 + 全绿数据看不出核心功能 | 用户打开看到空白，判断"不好用"就关掉，永远发现不了逾期处理能力 |
| 「按钮≥44px、输入框≥16px」 | iOS 对 <16px 的输入框会自动缩放页面 | 手机端一点输入框整页放大，布局错乱 |
| 「数据存 localStorage + 导出导入」 | 零服务端方案里，数据丢了就真没了 | 清一次缓存，几个月的记录归零 |
| 「主色 + 字体栈」定死 | 不给约束时 AI 会自选渐变紫、阴影、Inter 字体 | 出来一个"AI 味"很重的模板页，而不是能长期用的工具 |

一句话：**提示词的重点不是描述功能，而是封堵退路。** 凡是"做得好会给、做得差也不会报错"的地方，都得写成硬性要求。

## 3. 生成过程

### 3.1 实际走的五步

| 阶段 | 做的事 | 产出 |
|---|---|---|
| 1. 方案确认 | 检查在线存储能力是否可用；不可用则明确降级为「本地单文件 + localStorage」并告知用户 | 技术路线定下来，避免中途改存储层 |
| 2. 写骨架 | 一次性写入 HTML 结构 + 全部 CSS + 三个模块的挂载点与初始化入口 | 一个能打开、但内容为空的页面 |
| 3. 增量写逻辑 | 渲染层、交互层分两次写入（先用占位符 `/* __RENDER__ */`、`/* __EVENTS__ */` 占位，再分别替换） | 每次写入后文件都仍可运行 |
| 4. 运行时验证 | jsdom 跑断言测联动逻辑；真实 Chrome 截图测布局 | 78 项断言全过；4 档视口无溢出 |
| 5. 视觉打磨 | 逐张看截图，修月历被拉宽、图表起始值假、卡片底部不对齐等问题 | 最终版 |

**为什么第 3 步要分次写入**：单文件 1500 行、约 68KB，一次性生成很容易在中途截断或漏掉后半段，而截断的文件不报错、只是缺功能，比直接报错更难发现。先骨架、再分模块补齐，每一步都是可交付的中间态。

### 3.2 验证用了什么

不是"看起来能跑"，是实际跑过：

- **语法**：从 HTML 抽出 `<script>` 内容，`node --check` 检查
- **逻辑**：jsdom 加载页面，模拟点击，直接读 `localStorage` 里的数据断言状态。六条联动规则的正向、反向、删除对称、空数据、二次确认都覆盖，共 78 项
- **渲染**：`playwright-core` 调用本机 Chrome，在 1280 / 1180 / 390 / 360 四档视口截图，检查 `scrollWidth > clientWidth` 判断横向溢出，监听 `pageerror` 与 `console.error`
- **数据闭环**：真实点「导出 JSON」拿到下载文件 → 改一处内容 → 重新导入 → 读 `localStorage` 确认生效；再喂一个格式错误的文件，确认只弹提示、不破坏现有数据
- **零外链**：监听所有网络请求，确认除 `file://` 外没有任何外部请求

### 3.3 过程中修掉的典型问题

这些问题在静态审阅代码时都看不出来，只能靠截图和断言暴露：

| 现象 | 原因 | 修法 |
|---|---|---|
| 月历单元格被拉成横条，行高不一致 | `aspect-ratio: 1/1` 与 grid 的拉伸行为冲突 | 改为固定 `height: 52px` |
| 「全部」视图柱状图只有最后一根有数据 | 示例打卡只造了近 8 天 | 补一段覆盖 12 个月、越近越密的确定性历史 |
| 柱状图从 0 突然跳到 5 月 | 历史数据是硬造的，起点太整齐 | 用 `hashRand(i, hi)` 生成分布，形状自然 |
| 研究线卡片底部输入框高低不齐 | 卡片高度由内容撑开，底部未贴底 | `.prog-add` 加 `margin-top: auto` |
| 移动端某处出现横向滚动条 | 网格 `min-width` 超出视口 | 逐视图测 `scrollWidth` 定位后收窄 |

## 4. 验收清单

拿到一份 AI 生成的工作台，按这 18 条过一遍，能过的才值得长期用。

**数据完整性**
1. 双击打开首屏非空白，含至少 1 条逾期项
2. 四个维度 Tab 的统计数字与实际条目数一致
3. 添加任务 → 刷新页面 → 数据仍在

**联动（最容易假实现的部分）**
4. 任务关联研究线 → 看板出现同名进度任务
5. 看板添加进度任务（勾选同步今日）→ 今日出现同名任务
6. 「全部」添加任务 → 自动新建同名研究线
7. 任务勾选完成 → 看板进度任务变「已完成」
8. 看板点到「已完成」→ 任务自动勾选
9. 看板从「已完成」点回「待启动」→ 任务取消勾选
10. 删本月任务 → 看板对应进度任务消失
11. 删今日任务 → 看板进度任务保留，仅解除关联
12. 删研究线 → 弹二次确认，取消不删、确认才删

**日期与边界**
13. 逾期项点「顺延今天」→ 日期变今天、红标消失
14. 跨月、跨年打开页面，月历与本周网格不错位
15. 清空全部数据 → 页面不报错、不白屏

**技术底线**
16. 打开 DevTools 的 Network，除文档本身外无任何请求
17. 390px 与 360px 宽度下无横向滚动条
18. 全程 console 无报错

## 5. 换成你自己的场景

提示词的可替换点集中在这几处，其余部分基本通用：

| 占位 | 本项目取值 | 换法 |
|---|---|---|
| 工作台名 | 硕士学术工作台 | 改成你的身份 + 工作台，如「内容创作台」「考公台」 |
| 三个模块 | 任务 / 研究看板 / 习惯 | 最多留 3 个。超过 4 个必然崩，别贪 |
| 「研究线」 | 毕业论文、期刊投稿、课程论文、内容运营 | 换成你的 3-5 个长期项目。它们是联动的锚点，不能省 |
| 习惯 | 每日阅读、运动30分钟、每周输出 | 2-4 个，必须可每天判定是/否，别写"多读书"这种没法打卡的 |
| 主色 | `#3B5BDB` 靛蓝 | 换成你偏好的色值，其余颜色变量会跟随 |
| 优先级 | P0 / P1 / P2 | 若不需要分级，整段删掉，记得同步删掉表单里的下拉框 |

**两个改造示例**

内容创作者版：模块换成「选题看板（灵感→写作中→已发布）+ 素材库 + 数据复盘」；把"研究线"换成"内容系列"，联动逻辑照搬——选题关联系列，系列下自动出现同名进度项，发布后两边同时标记完成。

考公备考版：模块换成「刷题记录 + 错题本 + 每日打卡」；联动改为"错题加入错题本时，自动在当日复习任务里生成一条"；顶部置顶区改成"今日必刷 + 逾期未复习错题"。
