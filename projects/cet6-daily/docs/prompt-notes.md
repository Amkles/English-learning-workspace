## 一、总体要求

做一个单文件 HTML 的「六级打卡台」（CET-6 Daily）。

一个 `.html` 文件，CSS 与 JavaScript 全部内联，零外部依赖，双击就能用。图标全部手写内联 SVG，不许用 emoji 充当图标，不许引 CDN、框架、字体、图表库；图表（环形进度、热力图、条形图）用内联 SVG 手画。

数据存 `localStorage`，键名 `wb_cet6_data`，带 schema 版本号；旧存档必须能自动迁移，不许因为升级把用户记录清空。

三个页面：今日任务、目标与资源、打卡统计；加一个设置抽屉和一个独立的说明页。

## 二、硬性约束

**布局**

- 桌面：左侧固定侧边栏，含品牌名、三个主导航、设置入口、使用说明、保存状态
- ≤768px：侧边栏收起，改成底部四个 Tab（今日 / 目标 / 统计 / 设置），底部留 `env(safe-area-inset-bottom)`
- 窄屏一律单列堆叠，不许出现横向滚动

**可达性**

- 所有按钮的可点区域 ≥ 44×44px
- 输入框字号 ≥ 16px（低于 16px 时 iOS 会自动缩放页面）
- 尊重 `prefers-reduced-motion`

**内容**

- 题库必须是真实可用的条目，不许出现占位符、`example.com`、`xxx`
- 阅读与听力给真实页面链接，点了能打开
- 翻译与写作给完整题干与参考内容，不是标题党

## 三、页面一：今日任务

**顶栏**：问候语（按当前时段变）、日期、距考试天数、「本地已保存」状态点（保存中/已保存/失败三态）。

**逾期条**：昨天没做完的缺口默认并入今天，文案要说明并了什么；给一个「只做今天」的开关，关掉后不再顺延；昨天没有缺口时整条隐藏。

**进度卡**：环形进度 + 「今日已达标 N/5 项」+ 五个板块状态点；五项全清后整卡换成紫色徽标态；两个按钮「全部达标」（一键补齐）和「复制文案」（生成含单词与链接的纯文本，可粘贴到聊天窗口）。

**今日推送**：四列。

- 阅读 2 篇（易 1 + 难 1），每条显示序号、标题、来源平台、1–5 星、预计时长，一个「直达原文」按钮，打不开时提供「搜同题」
- 听力 1–2 个，显示标题、平台、分钟数
- 翻译 1 段，内置中文题干，展开显示参考译文与 2–3 条难点提示
- 写作 1 题，内置 Directions、三点提纲、三段框架、100–160 词范文、可替换词组

每条右侧一个「记一篇 / 记一个 / 记一段」，点了直接给对应板块 +1。

**单词区**：词库切换（见第四节）、每日量（10/15/20/30/40/60，默认 20）、三种模式、当前批次进度（「当前库 · 第 N/M 批 · 第 x–y 词」）。

**五项卡**：单词、阅读、听力、翻译、写作各一张，显示目标、已完成、缺口，配 `+1` 与「一键达标」。

## 四、单词板块

四个固定词库 + 一个自建生词本：

| 词库 | 词数 |
|---|---|
| 四级全库 | 2607 |
| 四级重点 | 1302（四级词表超出高考 3500 的部分） |
| 六级全库 | 2345 |
| 六级重点 | 1313（六级词表不在四级词表的部分） |

用公开开源词书派生（例：qwerty-learner 的 CET4_T / CET6_T 加 GaoKao_3500），释义截短去重到 3 个义项以内。

- 切库只换推进名单，按日期顺序往后推，翻完回开头；记忆状态与生词本跨库保留
- 三种模式：**卡片**（先遮释义、点卡翻面、按认识/模糊/不熟自评，模糊与不熟进生词本且隔天优先）、**自测**（四选一，错词自动进生词本）、**清单**（当批词一览带记忆状态点）
- 词卡显示词、音标、词性、释义、词缀提示、发音按钮（浏览器语音合成）
- 词缀提示宁缺勿错：后缀必须与词性匹配才给
- 词性缺失时整块不渲染，不留空占位（四级词书约六成词条没有词性标注）

## 五、每日抽取机制

这是最容易做错的部分，规则要一条条落实。

**冷却天数按池长反推，不许写死**：

- 阅读 1 篇/档，`rest = 该档池长`，两档独立
- 听力 1–2 条/天，`rest = max(6, round(池长 × 0.66))`
- 翻译单双日交替易/难，`rest = 当日档位池长 × 2`
- 写作 1 题/天，`rest = 池长`

**每条内容记录「上次出现在第几天」**，`今天 − 上次 >= rest` 才进候选。

**必须补位**：候选不够时按「最久没出现」补满，绝不返回空。

**同一天刷新内容不变**：用「当日种子 + 板块名」打乱，种子与结果一起落盘。

**题库换过要升池版本号**，旧版本当日结果作废重抽。

**阅读按难度分档**：≤3 星为易、≥4 星为难，两档完全独立轮转。

**听力按累计时长凑到 ≤30 分钟**；如果只凑出一条且不足 15 分钟，改用一条 18–30 分钟的单条顶替。

**每条内容只留最近 200 条出现记录/板块**。

**目标调大不会多推**：推送数量由池子规则决定，改目标只影响达标判定。

## 六、素材导入

用户会从 B 站、小红书、抖音直接复制分享文案粘进来。必须覆盖八种输入形态：

1. `标题 | 链接`
2. 标题一行、链接下一行
3. 只贴 `https://` 开头的链接
4. 无协议域名（`example.com/a`）与短链（`b23.tv/xxx`）自动补 `https://`
5. JSON 数组
6. `{items|list|data|result: [...]}` 包裹的 JSON
7. RSS / Atom：取 `<item>` / `<entry>` 的 title 与 link（含 `href`），处理 CDATA 与实体
8. `#` 开头的行当注释跳过

**标题清洗顺序不能乱**：剥分享尾巴 → 剥行首短码（`59 `、`7.43 `、`pMx:/`）→ 剥作者前缀 `【某某的作品】` 与引导语「复制打开抖音，看看」→ 剥 emoji 与 `#话题#` → 循环剥外层 `【】[]「」『』（）()《》<>` → 剥来源尾巴（`- 哔哩哔哩`、`_bilibili`、`- 小红书`、`- 抖音`、`- YouTube`）→ 剥残留的分隔符 → 标题不像标题时换平台占位名（B站视频 / 小红书笔记 / 抖音视频 / YouTube 视频 / TED 演讲），但中文 2 字标题要保留 → 无标题时从 URL 路径末段推。

**URL 截取必须排除中文标点** `，。；：！？、` 以及引号括号，否则「看这个 https://a.com/x，很有用」会把逗号吃进链接。

**平台识别**：bilibili / b23 → B站，xiaohongshu / xhslink → 小红书，douyin / iesdouyin → 抖音，youtube / youtu.be → YouTube，ted.com → TED，其余显示域名（超 18 字截断）。

**入库规则**：

- 自建条目当天至少露一条在最前，之后 7 天冷却轮转
- 每来源上限 300 条
- 解析 0 条时**不清空、不关弹窗**，提示正确格式
- 保存后立刻落盘、重建词库、重抽当天推送并刷新
- 素材地址可以试拉一次远程内容，但跨域失败要如实提示，不许假装成功
- 清空只清该来源的自建条目，内置题库不受影响

## 七、页面三：打卡统计

**四张数据卡**：连续天数、累计五项、本周达标率、距考试天数。

**区间**：30 天 / 90 天 / 6 个月 / 全部，影响汇总表与热力图，不影响各科达标率。

**汇总表**：五个板块的合计、日均、达标天数，按所选区间。

**热力图**：一格一天，颜色随达标项数加深，5 项全清用紫色，最多 26 周一屏看全，每格带 tooltip。

**各科达标率**：内联 SVG 横向条形图，按全部记录算。

**逐日记录**：按月翻，最多回看 6 个月。

**首次打开预置最近 6 天示例**，含完成与未完成，设置里可一键清掉。

## 八、打卡判定

- 五项全部达标才算当天成功，差一项也不算
- 昨天缺口默认顺延，可以手动切掉
- 达标 1→4 项颜色逐级加深，5 项全清用紫色

## 九、视觉

- 主色 `#D6336C`，背景 `#FCF2F6`，白卡片，圆角 16px，描边 `#F2DFE8`，轻阴影
- 板块色：单词 `#D6336C`、阅读 `#A8447F`、听力 `#6E5AA8`、翻译 `#D9822B`、写作 `#E0629B`
- 达标色阶：`#F2A6C6 → #E879A5 → #D84A7B → #B42557`，全清 `#5B3FA8`
- 系统字体栈，中文优先 PingFang SC / 微软雅黑
- 渐变克制使用，只在品牌标记与全清状态上出现

## 十一、设置与说明

**设置抽屉**：考试日期、每日提醒开关 + 时间、导出 JSON、导入恢复（支持上千条）、清空示例、清空全部（二次确认）。

**提醒边界要写清楚**：只做「打开页面时到点未打卡则提示」，关掉浏览器不会响，建议用系统日历。说明页里也要重申一次。

**说明单独成页**，分九节：每天怎么用、推送怎么抽、单词三种模式、素材来源、自建素材（含三平台粘贴示例）、统计口径、数据与备份、提醒边界、开发者信息与版本号。

## 十三、六条易错点

1. 冷却写死，没跟池长走 → 几天就抽到同一篇
2. 渲染用的池子和抽签用的池子不一致 → 界面显示的数量和实际能抽的对不上
3. URL 只按空格截断 → 链接后面粘着中文标点
4. 解析 0 条时当成「清空」处理 → 用户粘错一次就丢素材
5. 抽完不落盘 → 每次刷新内容都变
6. 删旧题库不升池版本号 → 存档里留着死 ID，卡片点开空白

## 十四、交付形态

建议拆成五个文件再合并，方便维护：

```
src/index.template.html   # 页面骨架，含 CSS/DATA/APP 三个占位符
src/style.css
src/core.js               # 数据与算法
src/views.js              # 视图，纯字符串拼 HTML
src/boot.js               # 交互，单一事件委托 + data-act
```

构建脚本把四份注入模板，产出单文件 `index.html`，并在注入前校验题库规模，不符直接失败。

运行期用 IIFE + 全局命名空间（`window.Core` / `window.Views` / `window.App`），不引入模块系统。

测试用 jsdom 跑，至少覆盖：素材解析 11 条用例、连续 400 天抽取（覆盖率、冷却、幂等、池版本号）、页面渲染与关键交互。
